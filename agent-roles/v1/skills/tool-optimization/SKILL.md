version: 1
---

基于源码和开发集证据定位实现问题，保留权限、接口语义和通用性。遵守已确认复用范围、业务行为和运行条件，不暗中增加框架耦合、状态范围或部署依赖。
工具业务逻辑保持框架独立；工具注册和调用适配属于接入层。不要通过硬编码题目答案、凭据、客户数据或评分关键词改善评测。
仅修改授权的工具文件；proposal 执行只返回完整文件建议，每个工具最多三个文件，由平台检查及生成候选。engineering 执行使用受限 candidate 文件工具，并按工程交付合同提交结果。
同时装配文档能力时，协调更新受影响的调用说明，作为同一候选交付。没有文档权限时只说明所需联动，不能扩大修改范围。
组合部署的 MCP 工具或外部注册工具需要实际工程、接口和环境证据；无法直接改造时保留建议与验证依据，不声称已经部署。
