# 事实归属修订：独立实验，非线上默认样例

旧 `examples/fact-check-demo/SKILL.md` 保持原样。这里新增0.1.1，仅加强主体、对象、日期、币种及范围归属，明确同时约束事实列举、限制说明和最后概括。没有写入原失败题的金额或日期答案，没有修改Host、Runtime、工具接线或Judge。

## 冻结

既有 `fact-provenance-v5` 批次在 v4 之上区分工作区读取收据和格式引文恢复；该批次及旧结果保留。当前策略为独立的 `fact-provenance-v6`：增加已绑定 Skill 制品内文件的精确读取摘要匹配，不暴露正文、不降低证据要求。脚本固定策略源码及证据模块的 LF 摘要，必须显式选择 v6 新批次；默认 v5 在当前源码下拒绝冻结，不能悄悄重标旧记录。Skill 两版与案例内容没有变更。使用旧 manifest 时必须检出它绑定的源码，不能拿当前评分覆盖旧结果。这是证据策略批次，不是 Runtime 或 Builder 协议升级。

当前已进一步演进为独立的 `fact-provenance-v7`：对既有 `skill_tool` 资源读取入口同样核对目标、相对路径与完整返回内容摘要，保留真实工具名。v6 源码摘要和失败结果继续保留，当前源码不能冒充 v5/v6 批次；需要显式选择 v7。

当前新增工具结果到后续输入的摘要匹配证据，冻结批次使用 `fact-provenance-v8`。它只证明按输入合同选取的值与实际参数一致，不证明内部因果或内存状态；v7 的固定源码摘要及历史结果不改写，当前源码不能冒充 v7。Skill 与测试题保持不变，批次版本不属于 Runtime 接口版本。

```sh
node examples/fact-check-attribution-v011/freeze.mjs /tmp/fact-attribution-cohort-v8 fact-provenance-v8
```

输出两个可上传ZIP、同一份8题测试集及96条执行计划。输出目录必须不存在；同名目录不能被覆盖。脚本检查旧Skill和Judge源文件摘要，**不执行模型**。

- 原4题的输入及逐项criteria来自已保留验收资料，不改分。
- 新4题在模型执行前冻结：明确共同日期正例、不同日期、不同主体、日期仅属于后一事实。
- 每个Skill × Runtime × 案例固定执行3次，共96次；每轮交替Skill先后顺序，不能挑一次最好结果。
- 同一模型、生成参数、可信业务日期、Runtime版本和Judge策略；实际配置有差异就停止该对照并说明，不能静默降级。
- 同一套Judge代码及来源检查用于两版，传入各自真实Skill合同；旧题的额外量表要求仍须如实标明。
- 故障、超时、取消、缺失结果全部保留在计划分母中，和回答FAIL分开。额外补跑另列，不替换原记录。Judge内部已有重试沿既有机制，不能按评分结果挑选。
- 先看原题是否回归，再单列新增冻结集；这些不是经业务Owner确认的独立盲测，也不用于判断Runtime整体优劣。

## 执行入口

在独立评测工作区上传两个ZIP，分别导入同一`suite.json`为独立副本。在“对比Runtime”中选择两端无工具环境，按manifest中的参数、版本与3个重复批次执行。每个批次记录run/report ID、内容及加载摘要、执行状态、评分与回收证据。

原报告和原评分不修改。只对执行完成者统计回答质量，同时另报计划完成率；完整96条执行结束之前不能宣布修订有效。首轮不把该修订替换为默认下载样例。
