# 无工具 Skill 页面验收样例

这个源码样例用于验证上传、依赖识别和双 Runtime 加载，不包含银行接口、密钥、真实客户数据或可执行代码。它不是 Dot 首次上传时的原 ZIP；本轮重新建立了可复跑的合成样例。

## 打包与上传

在仓库根目录运行（需要 zip 命令）：

```sh
zip -j /tmp/fact-check-demo.zip examples/fact-check-demo/SKILL.md
unzip -l /tmp/fact-check-demo.zip
```

归档中只应有 SKILL.md。复测时使用新的输出文件路径，避免 zip 命令将旧归档中的其他文件保留下来。

1. 用本人灵感账号进入 Finance Eval，打开「Skill 资产」。
2. 点击「上传 Skill ZIP」，选择归档；等待明确成功信息并核对资产名称与版本。
3. 点击该资产的「AI 生成试题」。检查生成案例只使用用户输入，requiredTools 为空；错误案例不可直接作为验收依据。
4. 点击「进入评测」，选择「对比 Runtime」。使用受支持的无工具环境，对照组 OpenJiuwen Java，目标组 AgentScope Java。不能以直连模型替代原生 Runtime。
5. 核对同一 Skill、模型及生成参数，运行测试。每侧分别查看回答、版本证据与评分。

预期：跨币种不直接相加；缺少余额不当作零；不编造查询或转账；回答包含 FACT_CHECK_DEMO_V01 和三个指定小节。标记只是行为核对，实际加载仍须核对安装 Lock、源摘要及 loadedSkillDigest。

## 迁移后继续测试

从此资产点击「发起迁移」，分析依赖。应明确没有业务工具依赖，而不是虚构工具。
在已准入环境中选择两个无工具 Runtime，核对要求并生成临时候选；无需正式发布。
下载候选 ZIP 并保存来源和版本记录，点击「在 Skill 资产中继续测试」，为候选生成试题后再次双端评测。
无工具方法不需要为了迁移强制改写正文。迁移前后的候选版本可不同，来源与方法正文必须可追溯。

## 必须分别记录

- 上传请求状态、资产 ID、内容摘要；操作超时不自动等于上传失败，先检查是否已保存，再决定重试。
- 功能执行、回答质量、实际加载、资源回收分别验收。两个 Runtime 有答案不等于四项均通过。
- 页面取消状态不证明进程回收；案例工作区 closed 不证明所有构建资源删除。
- 没有 Token 用量或网络参数证据时标为未采集，不推断零成本或参数已抓包核验。
- 无第二个账号则保留隔离未测，不借用其他人的会话或令牌。

此样例不承诺任意 Skill 一键适配：标准工具仍需合同与已准入实现；框架专用代码、记忆和工作流需要单独适配。
