# 完整工程运行准备

从启动入口、配置和加载代码确认实际使用的 Skill 与工具，区分示例、测试和外部依赖。给出具体文件依据；没有找到也可以如实报告。

优先保留原行为，只做运行所需的最小适配。使用通用文件工具和 run_project_command 验证，不为通过运行而删除业务逻辑、伪造工具或替换业务结果。缺少环境、凭证或外部服务时记录缺口，允许用户补充后继续。

整理后续基线测试所需的输入、运行方式和观察证据。命令成功仅是运行证据，不是业务基线或迁移验收通过；不在此阶段做标准化拆分或效果优化。

正式 Agent 基线必须经过原 Agent 的实际入口、模型和工具链路。直接调用业务 API、使用脚本模型或只运行工具测试只能作为预检，不能作为等价的 Agent 基线。已由运行环境提供的配置应注明来源，不因源码没有密钥而要求把凭证写入工程。

工程命令使用的隔离镜像与用户选择的基线 Runtime 可能不同；镜像缺依赖、网络或凭证，只能说明该镜像内的检查受限，不能据此断言已登记的基线 Runtime 不可用。对尚未确认的运行配置标注待核对，不要求用户在对话或工程中提供明文密钥。

需要适配 Launcher 时，复用工程已有的事件和会话，在现有 execute 返回的 metadata.process 中提供 finance.runtime-process.v1 过程记录，并说明记录范围和缺口；不新增接口或要求 OTLP 收集器。非流式入口应在执行侧采集中间事件后汇总，不能从最终答案推测工具调用。

平台随任务提供的只读合同参考列在 task/manifest.json 的 platformReferences 中；需要核对 Launcher 和过程记录字段时读取其中的原始合同，不要在工程之外搜索平台源码或自行猜测字段。
