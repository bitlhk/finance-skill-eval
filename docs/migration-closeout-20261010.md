## 本轮已发现并修复的阻断

全新上传报销 Skill，经真实源诊断、方案生成及明确确认后，A4 实际写入并测试了
`migration-skill/scripts/check_expense.py`、兄弟目录 `assets/rules.json` 和 SKILL.md。
平台将 Script 再打包成 `scripts/check_expense/scripts/check_expense.py`，破坏已测试的目录关系，
独立候选检查因 `scripts/check_expense.py` 引用不存在而阻断。这一轮是生成阶段失败，不能算 UI 通过。

修复：统一去掉 A4 的隔离交付根 `migration-skill/`，保留 Skill 相对脚本、资源和文档布局；
拒绝混用交付根，不能移动文件后强制改写模型已确认的文档。
模型可替换明确归属该批迁移工具的源资源，但多个工具对共享文件的不同交付仍拒绝，
未迁移工具使用的共享源资源不能被静默覆盖。

Script 真实 Runtime 挂载也统一以 Skill 根目录为边界，不能用脚本所在目录或最近的依赖清单目录
代替资源边界；包内 assets/、references/ 等资源不按扩展名丢弃。技术试运行和真实运行因此使用同一包内布局。
手工 UI 验收服务在启动前检查三仓测试范围无未提交差异，并记录版本；当前 native package
Launcher 不执行 Java Harness，报告明确记为 NOT_USED，不能用于证明 Harness 重建闭环。

验收汇总也补齐了门槛：必须具备当前方案、候选摘要、运行配置摘要、最终留出运行、
复用运行及验证导出身份。阶段名称、采用成功或下载成功本身不能将 Skill 标记为闭环。
全新总入口禁止复用源诊断、方案、A4、候选诊断或独立审查记录。

应收账款新版改为 `query_receivables → summarize_receivables`：查询保存完整快照，返回有限预览，
消费工具按用户选择使用同一快照。没有打开或关闭服务的业务工具；任务结束由运行系统销毁服务。
新任务重新查询，旧临时引用不作为跨部署可复用凭证。源实现离线回归不等于真实模型 UI 验收。

续测：即使 Runtime 与 Judge 全部重新执行，复用诊断、方案、产物或审查时仍归为续测，
不能计作当前版本从零完整迁移。失败原记录保留，修复复测使用新记录，不覆盖旧结论。

## 验收服务的版本隔离

Eval `ec038d80f4e41d0292dee0092ac3b306a338418e` 的新报销 UI 轮次完成了源诊断、
方案确认、生成、独立审查和技术试运行，但开发题三条都在 Judge 前执行失败。
Builder 的 Git reflog 记录了 17:48 切换到其他开发分支，17:57 的执行仍从原工作目录
加载 worker，而该分支不存在 worker 文件；Launcher 返回 `CASE_FAILED_INSTANCE_RELEASED`。
留出题未执行、未消费，没有采用或验证下载，不能计为业务评测或迁移通过。

手工验收服务改为导出固定 Builder commit 的已跟踪 workspace 源码，再从隔离副本启动。
Base 和 workspace 配置纳入启动前的干净检查；原目录的切分支或修改不会再影响 worker。
不复制未跟踪的 `.env` 或密钥，运行凭据仍只通过私有进程环境注入。该改变只影响验收
服务，不改 Builder 的业务契约，也不覆盖其他开发者的分支。

Eval `bb4da177e51586e28561f6d487645d71f94452e5` 隔离后的全新 UI 完成诊断、
方案、生成、审查和技术试运行，开发案例三条均执行完成、身份核实、Judge PASS，资源 RELEASED。
六项复用要求的计划生成七个动态案例，但独立覆盖审查仍为 INCOMPLETE；未运行留出题、
复用案例、采用或验证下载。该失败不能因业务 3/3 通过而改记为闭环。

其中“候选缺失脚本”是平台证据读取缺陷：`SkillStore.readFiles()` 是有意只返回文档
扩展名的投影，不能用于完整源码审查。实际归档包含 `scripts/check_expense.py`。
复用规划、覆盖与最终核对改用 `readArchive()`，复用现有完整文件数/摘要校验，严格解码
UTF-8 文本（包括 Python/JS），同时提供完整路径和未解码二进制清单；二进制存在不代表
其内容已检查。文件被改动时在模型判定前拒绝，不能读取未经绑定的源码。

规划指导也明确将原运行条件对应的静态事实放在相关原 check 的 checks.criteria，
而非只生成动态案例，或给原方案发明新要求 ID。部署前提、业务错误返回和进程异常
须按原条款及实际源码区分；版本不同先核对兼容性，不凭数字差异自动断言矛盾，也不
凭空断言已测量环境。覆盖审查保持独立，未覆盖仍阻断，不重试成通过。

## 按调用输入与迁移材料的阶段边界

Eval `1fc73e121fcc82ca2605120fb8201407df4ce58b` 的新 UI 源诊断将按调用读取的业务
数据标为 TOOL/KEEP、契约 KNOWN、实际值 UNKNOWN、blocking=true，静态诊断因此 PARTIAL。
没有进入方案、生成、业务、Judge 或留出评测。该记录保留，不通过提前上传测试数据规避。

修复显式记录有原文证据的 `executionInput`：仅 DATA/TOOL/KEEP、契约已知、无注入 binding
且输入证据验证通过时，缺少实际值不阻止迁移。仍保留 UNKNOWN/MISSING 和运行必需性，不编造
完整 Schema 或测试就绪结论。固定资源、配置、SDK、身份依赖与未知边界不能按此豁免。
前后端共用迁移缺项判断；页面显示“调用时提供”及输入依据，不要求保存真实数据为迁移材料，
服务器同样拒绝此操作。输入合同进入方案及独立审查，具体数据在运行参数或隔离案例中提供。
