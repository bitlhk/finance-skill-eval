# 迁移生成阶段的持久化与恢复

## 目的与边界

不因最后一步审查的格式、网络或进程故障丢失已完成工作，也不靠重复审查把负面结论变成通过。
本改造只完善迁移生成与检查底座，不代表业务评测、复用验收、Harness 重建或跨部署验收已经通过。

## 保存与恢复

迁移记录的 `generationAttempts` 保存每次生成的输入摘要、版本、执行进度、失败历史和阶段产物。

| 已保存阶段 | 恢复行为 |
| --- | --- |
| A4 交付 | 不重写代码，继续打包 |
| 候选资产 | 完整读取并验证不可变归档，继续检查 |
| 静态检查 | 不重复已完成扫描 |
| 候选实际分析 | 使用已保存事实，继续确定性核对与方案落实审查 |
| 完整方案审查 | 核对原结论并完成候选关联，不重复模型审查 |

待审资产只记录在生成尝试中。只有全部检查通过，才更新项目的 `candidate`、工具选择和候选历史。
失败或进程中断不会将待审资产伪装成可用候选；已有候选也不被半成品覆盖。

`POST /api/migrations/:id/generate` 增加可选 `mode`：

- `resume`（默认）：在相同输入下恢复未完成阶段；没有尝试时开始首次生成。
- `restart`：生成新产物，保留旧尝试、失败和审查结论。

恢复绑定源资产、基准资产、源诊断事实、材料摘要、工具形式与语言、用户已确认方案，以及平台交付/执行契约。
材料、相关事实或方案变化时不能沿用旧检查点，需要重新诊断或确认并生成。实际测试凭证值不进入生成摘要和模型上下文。
生成、审查与后续执行均以完整不可变归档为依据，包含脚本和资源，不使用只包含文档的投影。

进度持久化；当前服务没有活动请求但记录为 RUNNING 时，进度接口报告 INTERRUPTED。
页面刷新可重新获取活动状态；服务重启后允许恢复，不会自动重新请求模型。
阶段耗时不把已结束步骤的等待时间算进恢复调用；失败历史不会因为恢复成功而删除。

## 失败分类

格式、模型调用、扫描器故障等未取得有效结论的错误可恢复。失败记录包含阶段、稳定代码、公开说明和安全的字段路径，不保存原始 Provider/SDK 错误、模型响应或凭证。

明确的不能迁移、未解除耦合、依赖未确认、方案不符合或审查弃权必须处理原因。
`NEEDS_CHANGES` / `UNKNOWN`、业务语义漂移和新依赖结论被保存，不能对同一候选重复审查覆盖。
即使重新生成，若资产摘要与同一方案下已否决产物相同，也不会再次请求审查。
负面审查的源码引用有问题时同样保留结论，不通过“重新引用”把它变成批准。

## 验证要求

自动化回归验证持久化、重建服务后的恢复、源事实绑定、完整归档读取、错误脱敏、负面结论保留和旧候选隔离。
真实模型 UI 验收必须另外记录版本、是否恢复、各实际阶段和产物摘要；不能用上述故障注入测试代替。
发布签收仍须固定版本跑完整链路，保留独立留出结果，不能覆盖失败记录或把不同版本通过项拼成一次通过。

## 复用计划的证据边界

规划与覆盖审查使用明确的证据可见性说明。单案例 Judge 看到实际查询、输出、调用和已授权采集的结果投影，不会自动看到业务文件正文、工具原始实参、目录完整清单、执行源码或内部违规原因。可选摘要匹配与读取收据没有提供时，不能声称读取或因果关系已验证。

源码、规则、文档事实及跨案例宿主身份应在 check 层核对当前绑定的交付包和真实执行收据；案例层只核对实际可见的动态行为。判据位置可以修正，但原复用要求不能删减，也不能用模型推测补造证据。

缺少可选工作区读取收据、收据格式非法与已提供摘要冲突分别报告；不会把未提供收据误报为数据不匹配，更不会将缺失状态提升为成功读取。
