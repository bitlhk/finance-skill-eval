# Skill 迁移闭环修订与浦发样例检查

## 本轮结论

本轮补齐的是私有工作区的候选闭环，不是原生迁移成功证明。

- 修改、保存新版本、项目专属试卷、重新发起评测、完整导出已经接通。
- 完成同 Runtime 评测且具备冻结留出题后，可以调用既有优化器产生独立候选并复测；人工保留后可继续编辑、评测和导出。
- 浦发实包已完成导入、两次格式版本修改及导出检查。评测因缺少依赖映射被阻断；没有执行 Python、调用原生 Runtime 或真实模型。
- 自动优化的受控生命周期测试通过，不等于对浦发业务方法做了真实模型优化。

## 三项实现约束

### 候选与评测绑定

迁移项目绑定原始不可变资产、候选摘要及自己的试卷。优化只能从当前候选对应的完整运行发起，不接受其他项目的试卷或优化记录。候选在优化期间变更后，不能用旧优化结果覆盖新候选。

优化复测更新左右两侧的资产 ID，并将两侧绑定到同一目标 Runtime。不同 Runtime 的差异不能直接被当成 Skill 的缺陷。执行模型及参数必须相同。

优化候选的历史记录标为 `optimization`，不覆盖迁移原包。人工保留不等于迁移验收或正式发布。

### 完整但未验证的导出

导出保留全部原路径和文件字节，包括未验证的脚本、配置和根目录外依赖，同时附带：

- `migration-manifest.json`：逐文件 SHA-256、源/候选引用、未验证状态、禁止执行的归档说明。
- `migration-report.json`：对应项目及实验记录。

这与上一轮“遇到不支持的文件就拒绝导出”不同：本轮允许完整归档，但执行入口仍拒绝不能完整映射的依赖，不通过删除文件让测试过关。

若输入文件占用以上保留元数据路径，导出会拒绝，不能覆盖用户文件。此包不是安装 Lock，Builder 导入兼容性仍未验收。

### 项目试卷与留出题

项目试卷复用 PreparationStore，开发题与留出题分别保存，caseId 必须互不重复。修改试卷生成新的记录，不改变既有试卷。

迁移评测使用开发题；优化复测包含留出题，但编辑模型只读取开发题证据。没有留出题、存在执行/工具失败或无实际案例时，优化不能进入可保留状态。

## 浦发包实测

本机私有材料目录保留原始 RAR 及无损 ZIP 传输副本。本轮只读取 ZIP 内容，没有导入其中的 Python 模块。

| 检查 | 结果 |
| --- | --- |
| 原始包导入 | 通过 |
| 两个独立格式候选版本 | 通过，原始资产不变 |
| 项目自己的开发/留出试卷 | 保存成功；题目业务口径未获 Owner 验收 |
| 修改后重新评测 | 已实际发起，在 Runtime 调用前因依赖映射不全失败 |
| 基于失败运行自动优化 | 被拒绝 |
| 完整导出 | 通过，未修改的依赖逐字节一致，文件 SHA-256 匹配 |
| 正式发布 | 被拒绝，仍为 NOT_VALIDATED |
| 原生 AgentScope / Java Host | 未调用 |
| Python / 真实模型 | 执行次数均为 0 |

真实迁移仍需完整 AgentScope 工程、依赖锁、被省略的取数实现、只读测试环境，以及对原方法内部矛盾的业务确认。Java Host 适配和 Builder 导入仍有工程工作，不全部归为外部阻塞。

私有结果保存在本机 `inputs/pf-skill-migration/closed-loop-20260911/`，包含候选 ZIP、结果 JSON 和独立测试数据目录。客户材料没有加入 Git 或公开网页目录。
