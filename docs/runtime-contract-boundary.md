# Runtime 构建、启动与验收边界

本改造基于 Eval `45581f9` 和 Builder `finance`，对应 Builder Issue #49。
本文定义目标及实施检查项；未勾选项不代表已实现或已验收。

## 统一 Skill 集合

Runtime 只有一种实例启动请求：`skills[]` 与可选共享资源。一个成员和多个成员使用
相同协议、校验、装载、执行与清理流程。删除 `multiSkill` 能力开关和数量驱动的执行分流。
成员数量只属于容量限制，与文件数、总字节数、超时和并发上限一起公开。
全部成员在实例工作区内可发现；Agent 按任务选择读取和调用，不要求每个案例使用全部成员。

## 职责

- Builder 接收运行能力需求，装配或受控开发 Runtime，验证并交付可调用的部署。
- 部署管理独立托管 Launcher；构建结束和 Builder 重启不应停止已交付部署。
- Launcher 接收指令、Skill 集合、资源与配置，创建实例并管理资源归属。
- Eval 整体迁移和修复所选工作区，验收 Runtime 与具体输入、配置和数据集的组合。
- 构建需求不包含 Eval taskId/candidateId、业务 Skill 或留出集。Builder 使用自有验证资产。
- 新服务只接受标准协议；旧任务不转换、不恢复，历史数据不自动删除。
- 其他 Solution、Workbench、金融业务及公共 Base 协议保持自身边界。

## 绑定和失效

Runtime 交付绑定需求、制品、能力证据和部署。实例输入绑定 Skill、指令、资源及运行配置。
业务验收绑定 Runtime、输入、配置、数据集和 Judge。
Skill 修改使业务验收失效；能力仍满足时复用原 Runtime，使用新实例重新验收。
能力缺失才提出构建需求；部署过期、撤销或身份漂移阻止启动。
复用比较合同、协议、平台、权限、副作用、隔离、容量和验证证据，不仅比较工具名称。

## 生命周期

实例停止只影响本实例。清理未完成或失败时保留归属，禁止虚假 RELEASED。
部署停止先拒绝新实例，再处理在途执行与清理。客户端断连由租约/TTL 管理。
重启核对实际部署和进程代际，不自动重放业务。Linux、Windows、Docker 各自验证。
报价故障注入移出通用会话；撤权、在途等待、延迟清理和失败保留归属继续回归。

## UI

Eval 保留七阶段，将 Runtime 阶段整理为能力需求、Runtime 选择和实例配置；启动检查与业务验收分开。
删除单/多 Skill 模式、multiSkill 开关、旧任务桥接和 Builder 候选源码下载。
展示 Runtime 可用状态、当前输入版本和验收有效性；Skill 修改不提示必须重建。
Builder 构建页面仅接收能力需求，可选试运行页面通过标准启动接口注入 Skill。
两个产品入口独立，通过标准需求与交付协作。
