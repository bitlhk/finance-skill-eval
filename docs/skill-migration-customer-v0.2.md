# Skill 迁移：客户操作与交接 V0.2

## 本轮用途

将一个 Skill 的依赖、业务方法、资源和运行适配分开盘点，生成可交接的迁移版本。
不是任意框架自动翻译器；原工程缺失时不能证明等价。上传代码始终不被导入或执行。

## 四步操作

1. 在私有工作区选择 **Skill 迁移 → 导入 Skill**。可选择最多 10 个独立
   ZIP 或 Markdown，每个不超过 8 MB。一个 ZIP 只能包含一个 SKILL.md。
   每项独立创建项目；失败项显示原因，其他项目继续。Markdown 被作为独立方法导入。
2. 打开项目，查看 **依赖诊断**。处理方案分为可自动处理、客户确认、工程补齐。
   Python 使用 AST；Markdown 检查显式资源/宿主约定；Java 仅检查词法导入并明确
   保留语义分析缺口；其他代码语言未支持语义扫描。不把解析失败当没有依赖。
3. 点击 **生成迁移方案**，进入 **生成迁移版本**。已有经过登记的示例映射可选择
   并明确确认；其他工具生成待接线草稿。不会按名称猜输入输出，或给新 Skill
   借用财报模拟端口。生成后进入下一步，工程细节和 Schema 可展开查看。
4. **运行验证**独立显示目标执行与原环境效果对比。未接线的工具可以直接导出草稿。
   已支持的 OpenJiuwen 示例执行使用当前完整候选。正常、缺数和拒绝分别检查。
   **导出**生成方法、资源、声明、适配、变更列表与验证范围报告，不是正式发布。

## 修改后继续

在生成页面展开“手工编辑与已有候选”，读取原文并编辑迁移版本。保存会创建新版本，
旧包不变、旧验证和旧复核意见不用于新版本。

重新审阅映射并选择“保留修改并重新生成”，会继承当前方法和资源，而非从最初原包
重做。系统只重建其生成目录；检测到未知文件或已修改的适配文件时拒绝覆盖，交由
工程人员处理。它不支持自动合并任意客户改过的适配代码。

重新生成后再验证。手工修改没有直接获得执行权限；目标仍要核验工具集合、资源、
当前版本、完整包摘要与登记映射。每个项目只允许一项目标验证；单服务最多两项。

## 证明范围

| 结果 | 可以说明 | 不能说明 |
| --- | --- | --- |
| 静态诊断 | 已扫描范围与明确绑定、缺口 | 任意代码可运行或绝对没有依赖 |
| 迁移草稿 | 方法与资源被保留，有声明和适配建议 | 客户工具已实现 |
| 目标通过 | 当前候选在登记目标与示例数据上通过断言 | 原环境等价、真实银行接入、专业验收 |
| 专业复核记录 | 管理员对特定候选记录意见 | 已核实真人独立参与、自动发布资格 |

原环境效果对比与候选验证都通过已登记的 Runtime Launcher 启动本轮隔离实例。需要共同测试输入、可比业务数据/权限、
模型配置及差异记录；比较关键事实、任务结论、必要工具与拒绝行为，不要求文本逐字一致。
没有原工程与运行结果时标为待补，不伪装 AgentScope 已完成接入。

## 导出与敏感信息

`migration-manifest.json` 的状态区分 `DRAFT_NOT_VALIDATED` 和
`TARGET_VERIFIED_CANDIDATE`；两者均不代表正式发布。
`migration-report.json` 改为 `migration.export-scope.v1` 摘要，不再携带完整
模型回答、测试报文或原实验配置。读取旧完整报告的消费者应改用工作区报告 API，
不能继续假定导出摘要包含整个内部项目对象。

候选文件保持原字节（除用户明确保存和生成说明记录的变更）。导出检查常见凭据路径
和字面量，疑似凭据时拒绝；这不是完整 DLP。用户自己的业务方法和资源可能包含
私有内容，分享前仍需审阅。上传含多个 SKILL.md 的包现在明确拒绝，请拆为独立包。
导出重导入可作为资产保留；带交换元数据的包不是自动可再次发布的工程。

## 新工具怎样接线

`migration-generated/neutral-contract.json` 是版本化的中立声明提案，不是已安装的
Harness Capability Pack。源函数签名也不等于完整 Schema。接入人员应提供：

- 工具用途、权威输入输出 Schema、单位、来源和缺数/拒绝语义。
- 明确的 Host 适配与可信身份/权限来源；业务实现不得靠导入未审阅上传代码补齐。
- 方法可见资源与工具专用资源映射，实际 SDK 版本和冻结测试条件。
- 原环境基线、目标正常/缺数/拒绝测试及独立专业复核。

本轮继续使用小型已登记目标描述，不新增插件平台或自动安装第三方依赖。
AI 解释关联静态证据，不能产生工具实现、授权或等价证明；解释任务串行处理。

## 本地验证入口

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm build
VITE_PRIVATE_WORKSPACE=true pnpm exec vite build --base=/migration/ --outDir=../web-dist-private
MIGRATION_TEST_WEB_DIR=web-dist-private MIGRATION_TEST_PREFIX=/migration/ MIGRATION_TEST_PRIVATE_GATEWAY=true node scripts/verify-migration-ui.mjs reports/migration-customer
```

受控协议测试和浏览器操作不等于真人独立接入。真实模型＋合成端口验证另记，
不把它扩大成真实客户数据、原银行等价或实际业务效果验收。
