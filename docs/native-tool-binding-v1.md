# 受管原生工具绑定 V1

## 用户入口

本轮支持 OpenJiuwen Java 0.1.15、AgentScope Java 2.0.3 的受管只读工具。
HTTP/JSON Launcher 负责临时实例，不是 A2A；每题创建新会话，运行结束回收实例与案例工作区。

三条入口共享相同评测流程：

1. 精选技能：管理员安装固定摘要的“账户余额核验”样例后，选择该版本和双 Runtime。
2. Skill 资产：上传方法 ZIP，准备案例，选择已准入工具支持的 Runtime。
3. Skill 迁移：上传、诊断，在“复用已准入工具”选择两端，核对合同后生成不可变候选，再进入 Skill 资产评测。

第三条是复用现有实现，不生成银行代码。它不等于任意脚本或 MCP 代码已经迁移。
已有 MCP/Script 迁移流程仍保留，不能因原生绑定而绕过其独立门禁。

## 准入与冻结

Launcher 的 `GET /v1/native-tool-catalog` 返回运营者准入的工具合同、约束、验证摘要和部署身份。
它与五个生命周期接口使用相同认证，不公开凭据、源验证文件路径或服务器文件。

绑定要求：

- 完整诊断当前资产；未知外部依赖仍阻断。
- 所有业务工具、Runtime 工具都在目标目录中，名称与合同明确匹配。
- 两端合同与执行约束一致。源文件已有 Schema 时不能静默替换为不同 Schema。
- 只接收方法与声明文本，不执行上传代码。
- 目录版本变化、候选变化、漏绑工具时重新核对，不继承旧验证结论。

候选中的 `references/finance-native-bindings.txt` 关联源摘要、两端目录及制品摘要、工具合同摘要。
生成候选不要求正式发布，但也不代表执行或专业质量已通过。实际运行由 Builder 再检查绑定、安装资格和授权。
目录项的权限是要求，不是向用户授予权限。

## 预制范围

“账户余额核验”只使用 `account_balance_query` 和 `read_case_file`，在合成银行验证。
安装命令及文件位于 `examples/native-readonly-balance/README.md`。
Wind、保险、信贷、反诈等已有预制技能保持原始依赖。目标环境缺少它们的工具时，页面列出缺项并阻止开始。
不得用余额工具替代这些业务工具，也不得把框架可选标成业务已接通。

## 构建交付

Builder 需求契约接收、构建、启动及安装核验后返回交付结果；探针实例回收，Launcher 保持可申请状态。
Eval 接收交付时还要执行创建、状态、运行证据和删除检查。
验收使用当前方法源码、摘要和工具依赖，不再强制使用 Harness 不支持的无 Skill 实例。
声明文件工具的方法需验证实际文件调用；没有声明文件工具的生命周期检查不声称覆盖文件读取。
业务合同测试、生命周期连通和业务回答质量是三个独立结论。

## 私有入口

2026-10-04 起目标为所有已登录灵感账号可用，不设置管理员白名单。
候选 `account` 模式按可信 `studio_*` 主体隔离个人资产与运行记录，写操作校验 Origin。
用户不在浏览器输入服务端令牌；网关先完成真实灵感平台登录，再覆盖并转发可信主体。
旧工作区仅映射给原所有者，不向新账号共享。受管执行环境不可由普通页面修改连接或凭据。
详见[账号工作区部署说明](account-workspaces.md)。受控身份测试不等于实际 SSO 登录验收；
启用配置前仍须完成网关登录、伪造头拒绝、两账号隔离及回滚验证。

## 验收命令

```sh
pnpm check
pnpm test
pnpm build
```

隔离原生 Launcher 验收需要维护者提供当前资格文件、合成银行和受管模型，不能直接指向生产客户。
`scripts/verify-launcher-ui.mjs` 覆盖上传、预制、迁移页面路径；`scripts/verify-native-build-delivery.mjs` 覆盖真实构建交付与 Eval 再准入。
真实模型与受控模型报告分开保留，失败/超时记录不能删去后只报告成功。
