# 诊断依赖分类与提前连通验证

日期：2026-09-17。

实现将必需的静态诊断与可选测试配置分开：Runtime 实际值缺失不阻塞迁移，Tool 必需代码缺失或依赖契约未知需要补充后继续分析。逐工具显示迁移形式与语言、源码链路、Runtime/Tool/待确认依赖；共用依赖单独展示。

测试配置不进入 A2、A4 或迁移项目报告及交付包。提前接口检查仅限确认的只读 GET/HEAD，不跟随重定向、不保存响应。生成后使用保存的配置执行实际工具；配置或契约变化使旧结果失效。OpenJiuwen 使用配置引用在执行时解析依赖，凭证和上下文不进入模型填写的业务参数。

验证：

- Core/Web TypeScript 检查和 Vite 构建通过。
- 诊断、迁移、导入、测试集、语言与 Runtime 相关回归共 64 项通过。
- Python 运行依赖契约测试 3 项通过，覆盖缺少实际凭证时不执行业务代码、仍检查入口，以及 MCP 延迟实际调用。
- 浏览器验证通过共享依赖与单工具补充、SDK 补充后继续分析、形式和语言保留、可选凭证填写、真实只读接口访问、配置修改失效、刷新恢复和窄屏布局。
- 实际 Node 脚本携带注入凭证访问本地业务接口通过；实际启动的 MCP 服务两次调用使用不同凭证通过，凭证不进入业务参数。
- Python 修改文件语法检查和 diff 空白检查通过。

诊断与生成 agent 在自动化中使用固定分析/交付夹具，引用仍经过真实平台核对；业务 HTTP、脚本和 MCP 进程实际执行。没有以固定夹具验证真实大模型的依赖识别质量，也没有验证生产企业身份体系或自动凭证刷新。
