# 应收账款核对

1. 调用 `query_receivables(customer_id)` 查询真实业务数据。大明细保存在工具侧的本次查询快照，模型只收到记录数、前十笔发票的简要信息及精确 `snapshot_ref`。`preview_complete=false` 时，预览不是完整账本。
2. 核对全部账款时调用 `summarize_receivables(snapshot_ref)`。用户选择特定发票时，将同一次查询的 `snapshot_ref` 和选择的 `invoice_ids` 传给该工具；工具读取已保存的完整明细并计算，不能把预览当成全部数据、猜测金额或更换引用。
3. 根据实际结果答复。空账本输出零笔零金额；客户不存在明确报告。引用无效时重新查询已知客户，不编造引用；发票选择无效时请用户确认选择，不悄悄改成全量汇总。

这些业务工具的实现都在 tools/ledger.py；原先通过 tools/register.py 注册给 Agent。上下文就是这个业务模块自己的 `_snapshots`，不依赖模型记忆或框架的隐式全局状态。迁移时应保留查询和消费逻辑，在同一任务的工具服务内共享快照，不能把业务工具转给 Builder 重写。服务资源由运行系统管理，用户无需打开或关闭服务器。一个任务结束即销毁对应 MCP 服务；新任务或新部署必须重新查询，旧快照引用不要求跨部署存活。如果方案要承诺跨任务继续消费旧快照，应先说明现有内存实现不能满足，不能用临时引用声称已经可复用。

工具执行失败时说明具体限制，不根据用户提示猜测余额。工具只读业务明细，不催款、记账或改变业务系统。业务日期由服务数据给出，不要求用户额外配置。
