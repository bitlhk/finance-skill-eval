# 证据与覆盖率判据

## 一条发现算不算证据

必须同时满足：

1. `path` 指向工程里**真实存在**的文件；
2. `line` 是**真实的行号**，落在该文件的行数范围内；
3. 如果有原文片段，它必须能在该行（或给出的行区间）里**逐字找到**。

**三条缺一条，这条发现就会被平台丢弃**——不是你写得不漂亮，是它落不到源码上。

所以：**先定位，后表述。** 找到一个能对上的位置，再写这条发现。凑不出来的，宁可不写。

## 覆盖率：回答"我漏了什么"

平台有一个确定性的静态扫描器（`run_scanner`）。它的作用是**枚举全部文件并报告哪些读不了**（二进制、超限）。

**它比你自己读文件可靠，因为它回答的是"没看的"，而你只能回答"看到的"。**

- 动手之前先调 `run_scanner`，拿到确定性发现与覆盖率；
- 覆盖率不全时，在 `coverageGaps` 里**如实列出**漏看的部分；
- **不要**用"我大概扫过了"代替覆盖率声明。

覆盖率不全会导致平台要求人工确认后才能继续生成——这是设计如此，不是报错。

## 弃权

证据不足、或关键文件读不了时，把 `status` 置为 `ABSTAINED`，写清 `reason` 与 `missing`。

**弃权是合法的产出，不是失败。** 编一个看起来对的结论，比诚实弃权有害得多。
