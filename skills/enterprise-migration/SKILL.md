# 企业 Skill 迁移：判断依据

这是迁移平台自己的判断依据，不是要求被检查的工程遵守的新文件。

**改动交付形态的规则不在这里**——服务怎么写、怎么起、怎么被验，属于改造阶段，在另一个技能包 `enterprise-migration-delivery` 里。本技能包只负责**读这个包并给出判断**。

## 读哪一份

| 你要判断的事 | 读哪一份 |
| --- | --- |
| 一条结论算不算证据、覆盖率怎么看、什么时候弃权 | `references/judgement-rules.md` ① |
| **这个 Skill 用到了哪些工具、每个的输入输出和样例是什么** | 同上 ② |
| Skill 文档是否符合企业规范 | 同上 ③ |
| 某个 Tool 属于哪个可移植性状态 | 同上 ④ |
| 该建议它用 MCP 还是 Script、用什么语言 | 同上 ⑤ |

**就一份，整份读完再动手。** 四件事共用同一套证据要求，分开读只会漏掉约束。

## 四条不可违反的规则

1. **可以少报，不可以编造。** 证据不足时弃权，不要猜。
2. **每条发现必须可定位。** 文件、行号、原文片段三者缺一不可；落不到就不要写。
3. **分析读出来的东西同样要可定位。** 工具的输入输出和样例，也要指到文件与原文——落不到就不成立。
4. **授权的边界不在这里。** 这个工程**允不允许**被迁移，是人的决定；本技能包只负责技术判断。
